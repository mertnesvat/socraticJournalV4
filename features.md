### 2. Breath Patterns and Session Engine

Build the core domain logic: the breath pattern definitions and the session engine that manages phase transitions, timing, and breath counting. This is the brain of the app -- no UI yet, pure logic.

**User Story:**
As a user, I want the app to accurately pace my breathing through precisely timed phases (inhale, hold, exhale) for different scientifically-backed patterns so that I can follow a reliable, accurate guide without worrying about counting myself.

**Acceptance Criteria:**

Two MVP patterns:
- Resonance Breathing: 5.5 seconds inhale, 5.5 seconds exhale, no holds. ~5.45 breaths per minute. The "perfect breath" from James Nestor. Best for daily wellness and HRV.
- Coherent Breathing: 6 seconds inhale, 6 seconds exhale, no holds. 5 breaths per minute. Slightly slower variant, good for deeper relaxation.

Session engine behaviour:
- Engine accepts a BreathPattern and a target duration (5 or 10 minutes for MVP)
- Engine manages a state machine: idle, active, paused, completed
- When active, engine cycles through the pattern's phases in order, tracking elapsed time within each phase and total session elapsed time
- Engine provides current phase, progress within current phase (0.0 to 1.0), time remaining in current phase, total breaths completed, and total elapsed time
- Phase transitions happen precisely at the defined duration boundaries
- Session completes when total elapsed time reaches the target duration, but always finishes the current breath cycle before ending (do not cut a breath short)
- Pause freezes all timers; resume picks up exactly where paused
- Engine produces a completed BreathSession record with accurate statistics when session ends

Duration picker:
- Two options for MVP: 5 minutes and 10 minutes
- Default selection is 5 minutes
- Duration picker is a simple segmented control or pill selector

Edge cases:
- If user pauses at 4:58 of a 5-minute session and resumes, the session should still complete the current breath cycle after reaching 5:00, not end mid-breath
- Engine timer resolution should be high enough for smooth UI animation (60Hz or display-link driven)
- Engine must be safe to observe from SwiftUI views (@Observable, @MainActor)
- Pausing and resuming multiple times should not drift timing or lose state
- If the app goes to background during a session, the engine should auto-pause and resume when foregrounded

Verification:
- Unit tests can instantiate the engine with Resonance pattern, run it, and verify phase transitions happen at correct times
- Unit tests can verify session completion produces accurate BreathSession data
- Unit tests can verify pause/resume does not affect timing accuracy
- Engine works correctly with both MVP patterns
- Duration picker state is correctly passed to engine

**Dependencies:** 1

### 3. Breathe Screen -- Animated Breath Guide

The centrepiece of the app: the visual breathing guide that users follow during a session. A mountain/triangle wave animation with a calm phase label and subtle haptic feedback.

**User Story:**
As a user doing a breathing session, I want to see a beautiful, calming animation that clearly shows me when to inhale, hold, and exhale, with a gentle phase label and subtle haptic feedback, so I can follow along effortlessly without needing to think or count.

**Acceptance Criteria:**

Mountain/triangle wave animation:
- A horizontal line is drawn across the screen, live, as the session progresses
- On inhale: the line rises from baseline to peak, forming the ascending side of a triangle/mountain
- During hold at peak: the line stays flat at the peak level (if the pattern has a hold phase)
- On exhale: the line descends from peak back to baseline, forming the descending side
- The line is drawn progressively from left to right, like a seismograph, with the current drawing point always visible
- Path uses soft, rounded vertices (not sharp corners) at the peak and valley transitions
- Line colour: teal accent, with a subtle glow/bloom effect on the drawing point
- The path scrolls or wraps when it reaches the right edge of the screen, creating a continuous wave
- Background: deep navy, with the colour arc subtly transitioning from deep navy at session start toward warmer blue-teal as the session progresses

Phase label:
- Large, calm, lowercase serif text centered on screen: "inhale" / "hold" / "exhale"
- Font: the new `phaseLabel` serif font from the design system (Georgia or New York, 34pt)
- Phase label transitions use a soft fade animation (crossfade, ~0.3s)
- No other text clutter during active session -- the label is the only prominent UI element besides the wave

Haptic rhythm:
- Soft taptic pulse (UIImpactFeedbackGenerator .soft) on each phase change (inhale to hold, hold to exhale, exhale to inhale)
- Medium haptic (UIImpactFeedbackGenerator .medium) when the full session completes
- No continuous haptics during phases -- only at transitions

Minimal session UI:
- The wave animation and phase label are the primary visual elements
- A quiet progress arc (thin circular arc) in the top corner shows session progress (0% to 100%), using muted teal on dark background
- No visible play/pause/stop buttons during active session
- Single tap anywhere on the screen toggles pause/resume
- When paused, the wave animation freezes, the phase label shows "paused" in lighter opacity, and a subtle resume prompt appears
- Double-tap or swipe down to end session early (with confirmation)

Background colour arc:
- Session background starts as deep navy and subtly, gradually transitions toward a warmer blue-teal over the full session duration
- This should be a very gradual shift, barely perceptible moment to moment but noticeable comparing start to end
- The transition creates a sense of progression and calm deepening

Peak glow:
- During hold phases at the peak, the drawing point pulses with a gentle glow effect (opacity oscillation or subtle scale pulse)
- This reinforces that the user should hold their breath at this moment

Pre-session countdown:
- Before the session begins, show a 3-2-1 countdown with large serif numbers, each fading out
- After "1" fades, the first "inhale" phase label appears and the session begins

Session flow:
- User selects a pattern and duration from the Breathe tab
- Pattern/duration selection UI is simple: pattern name cards and a duration pill selector
- Tapping "Begin" triggers the countdown, then the active session
- Session runs until duration is reached (completing the current breath cycle)
- Session transitions to the summary view (Feature 4)

Edge cases:
- Wave animation must perform at 60fps without frame drops
- If user locks screen during session, engine pauses automatically
- If user receives a phone call, engine pauses automatically via scene phase detection
- The wave path must handle sessions of both 5 and 10 minutes without visual issues
- Accessibility: VoiceOver should announce phase changes ("inhale", "hold", "exhale") at each transition
- Reduced Motion preference: if the user has Reduce Motion enabled, simplify the wave to a static indicator with just the phase label and progress arc

### 6. Streak Tracking and Weekly Goal

Track consecutive daily practice and weekly minute goals to build habit formation.

**User Story:**
As a regular user, I want to see my streak of consecutive practice days and my progress toward a weekly breathing goal so that I feel motivated to maintain my daily habit and see my cumulative effort.

**Acceptance Criteria:**

Daily streak counter:
- Counts consecutive days where the user completed at least one breathing session
- A "day" resets at midnight local time
- Streak number displayed prominently on the Today tab (inside the streak ring)
- Streak persists across app launches (stored in UserDefaults alongside session history)

1-day grace window:
- If the user misses one day, the streak does not immediately break
- Instead, on the next day without a session, the streak shows a warning state (amber ring colour instead of teal, label says "streak at risk")
- If the user completes a session on the grace day, the streak continues unbroken
- If the user misses a second consecutive day, the streak resets to 0
- Grace window state is tracked in stored data

Weekly goal:
- Default weekly goal: 35 minutes of total breathing per week (approximately 5 minutes per day, 7 days)
- Weekly goal is configurable in Settings (options: 15, 25, 35, 50, 70 minutes per week)
- Progress ring on the Today tab shows weekly minutes completed vs goal
- Week resets on Sunday at midnight local time
- Progress ring uses a secondary ring or bar below the streak ring

Display on Today tab:
- Streak ring (primary, top): current streak day count
- Weekly progress indicator (secondary, below streak): "23 / 35 min this week" with a progress bar or secondary ring
- Both update immediately after completing a session

Local persistence:
- Streak count and last-session date stored in UserDefaults
- Weekly goal preference stored in UserSettings
- Streak calculation derived from session history dates (source of truth), not a simple counter

Edge cases:
- Timezone changes: use the user's current local timezone for day boundaries
- If the user changes their device time manually, streak is based on session timestamps (which use Date())
- First session ever: streak starts at 1
- Session completed at 11:59 PM and another at 12:01 AM: counts as two different days, streak advances to 2
- App reinstall: streak and history are lost (UserDefaults cleared) -- this is acceptable for MVP
